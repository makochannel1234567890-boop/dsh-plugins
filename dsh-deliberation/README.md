# dsh-deliberation

長考モードのための DeepSeek Harness バンドルです。モデルが長時間の熟考が必要と判断したとき、
セッション内の質問ポップアップで**人間の承認**を取り、承認後はターン終了ごとに
自動で次の熟考ラウンドを開始します。予算・停滞・ユーザー優先の安全弁つきです。

## 使い方

- 「この設計を長考して」「熟考して」のように頼むと、モデルが `deliberation_start` を呼びます。
- 承認ポップアップで「承認して開始」を選ぶと、指定予算で自動継続が始まります。
  Git リポジトリ内ならワークツリー隔離も選べます。
- 途中で止めたいときは、新しいメッセージを送るか、モデルに `deliberation_end` を使わせてください。
- 既定は 8 ラウンド / 45 分です。

## 何が起きるか

1. モデルが `deliberation_start` を呼ぶ（長考・熟考・open-ended な調査を頼まれたとき）。
2. 組み込みの質問 UI が表示される:
   - 承認 / キャンセル
   - Git リポジトリ内なら「ワークツリーで隔離するか」
3. 承認すると、必要なら `ctx.worktrees.create` で隔離し、`.dsh-deliberation/` に
   長考ブリーフ（目的・予算・作業ツリー・開始時刻）を書く。
4. 以後、ターンが終わるたびに `<deliberation_round>` プロンプトを次ターンとして投入する。
5. 次のいずれかで自動継続を停止する:
   - `deliberation_end` が呼ばれた
   - ラウンド上限 / 壁時計上限
   - 直前ラウンドと同じ応答・同じツール呼び出しの反復（停滞）
   - 新しいユーザーメッセージ（ユーザー優先）
   - `turn/end` が completed 以外（max-tokens, aborted など）
   - エラー、またはプラグインのアンロード
6. 予算切れ・停滞時は「最終レポートを書いて終了せよ」という1回だけの促しを入れて終わる。
7. ワークツリーを使った場合、停止時に元の作業ディレクトリへ戻る（設定で変更可）。
   ワークツリー自体は削除しない。

## 設定（`cordis.patch.yml` の `config`）

| キー | 既定 | 意味 |
|---|---|---|
| `defaultRounds` | `8` | 承認時に提示する既定ラウンド数 |
| `maxRounds` | `24` | ラウンド数の絶対上限 |
| `defaultMinutes` | `45` | 既定の壁時計予算（分） |
| `maxMinutes` | `120` | 壁時計予算の絶対上限 |
| `offerWorktree` | `true` | Git リポジトリでワークツリー隔離を提案する |
| `restoreWorkingDirectoryOnStop` | `true` | 停止時に元のディレクトリへ戻す |
| `stagnationRepeats` | `2` | 何回連続で同内容なら停滞とみなすか |

## 注意

- 状態はプロセス内メモリ（Agent オブジェクト単位）です。Harness 再起動やセッション再開を
  またいだ自動継続はしません。残る成果物は scratchpad とワークツリーです。
- ワークツリー隔離は Git リポジトリ内でのみ利用できます。
- 承認ポップアップには人間の回答が必要です。委譲された子エージェントからは開始できません。
- 壁時計上限はターン境界で判定します。1ターンが上限を超えて走り続けた場合、そのターンを
  強制中断はしません（ターン終了時に停止判定します）。
